# Flash-memory-managment

Лог-структурированная файловая система поверх SPI NOR флеш-памяти
Winbond W25Q32FV/W25Q64FV, реализованная в пользовательском пространстве
Linux (Radxa ROCK 3A, RK3568) через собственный character-device драйвер
ядра.

Стек включает:

- драйвер ядра `w25q_cdev` (SPI ⇄ `/dev/W25Q64FV`);
- низкоуровневые операции с флешем (`page_program`, `sector_erase`,
  `read_data`) с wear-leveling таблицей секторов;
- экстенты (`extent_t`) для фрагментированной записи данных;
- inode-таблицу файлов (`file_inode_t`) с зеркалированием и generation-
  версионированием;
- файловый API (`write_file` / `read_file` / `delete_file`);
- garbage collector, уплотняющий фрагментированные сектора;
- импорт/экспорт файлов между Linux ФС и флеш-ФС.

## Структура репозитория

```
module_kernel/       драйвер ядра (character device) для W25Q32FV/W25Q64FV
flash_ops/            SPI-операции + учёт секторов + экстенты (write_data)
file_system/          extent.h, indode.h, FS_fops.h (inode-таблица, GC),
                      load_export_f.h (импорт/экспорт с Linux ФС)
main.c                CLI-утилита для тестирования
run_fs_tests.h        интеграционный тест (запись, фрагментация, GC)
Makefile              сборка main
```

## Требования

- Radxa ROCK 3A (или другая плата с RK3568) под управлением Linux с
  заголовками ядра, установленными для сборки внешних модулей.
- Микросхема SPI NOR (W25Q32FV/W25Q64FV), подключённая к одному из SPI-
  контроллеров платы.
- `gcc`, `make`.

## 1. Настройка Device Tree

Драйвер регистрируется по `compatible = "egor,w25q32fv"` на шине SPI.
Нужно добавить соответствующий узел в device tree платы (или собрать
overlay) с этим `compatible` и указанием SPI-шины/CS, к которым
подключена микросхема — по аналогии со стандартным SPI NOR узлом,
но с этой строкой совместимости вместо `jedec,spi-nor`.

Соберите overlay и примените его (пример для Rockchip):

```bash
dtc -@ -I dts -O dtb -o my-overlay.dtbo my-overlay.dts
sudo cp my-overlay.dtbo /boot/dtb/rockchip/overlay/
# добавьте overlay в конфиг загрузчика (extlinux.conf / armbianEnv.txt)
# и перезагрузите плату
```

Точный способ применения overlay зависит от вашего загрузчика и
дистрибутива — свериться стоит с документацией для конкретного образа,
установленного на плате.

## 2. Сборка и загрузка драйвера ядра

```bash
cd module_kernel
make
sudo insmod w25q_cdev.ko
```

При успешном `probe()` в `dmesg` появится JEDEC ID микросхемы и номер
major/minor устройства:

```bash
dmesg | tail
```

Драйвер сам создаёт узел `/dev/W25Q64FV` через `device_create()` —
дополнительный `mknod` не требуется.

Проверить, что модуль загружен:

```bash
lsmod | grep w25q_cdev
ls -l /dev/W25Q64FV
```

Выгрузка модуля:

```bash
sudo rmmod w25q_cdev
```

## 3. Сборка пользовательской утилиты

```bash
make
```

Соберётся исполняемый файл `./main`. Все операции с флешем требуют
прав доступа к `/dev/W25Q64FV`, поэтому запускать нужно через `sudo`
(или настроить udev-правило на нужную группу).

## 4. Первый запуск — форматирование флеша

Перед первым использованием (и при любом ручном `chip_erase`) нужно
заново инициализировать служебные таблицы:

```bash
sudo ./main --reset_flash
```

Это стирает весь чип и создаёт заново:

- таблицу учёта секторов и wear-leveling (`tables[]`, 4 зеркальные
  копии);
- inode-таблицу файлов (`inodes[]`, 4 зеркальные копии, все слоты
  пустые).

## 5. Команды CLI (`./main <команда> [аргументы]`)

| Команда | Аргументы | Описание |
|---|---|---|
| `--reset_flash` | — | Полное стирание чипа (`chip_erase`) и повторная инициализация таблицы секторов и inode-таблицы. Уничтожает все файлы. |
| `--write` | `<имя_файла> <размер>` | Генерирует `<размер>` случайных байт и записывает их как файл `<имя_файла>` (создаёт новую запись в inode-таблице через `write_file`). |
| `--read` | `<имя_файла> <размер>` | Читает до `<размер>` байт файла `<имя_файла>` и печатает начало содержимого в hex. |
| `--del` | `<имя_файла>` | Помечает файл удалённым в inode-таблице (`delete_file`); физическое место освобождается позже сборщиком мусора. |
| `--inode` | — | Запускает сборщик мусора (`garbage_collection`): находит сектора с высокой долей "мёртвых" данных, переносит ещё живые файлы из них в новое место и стирает освободившиеся сектора. |
| `--test` | — | Прогоняет встроенный интеграционный тест (`run_fs_tests`): форматирование, запись обычного и фрагментированного файла, удаление, запись в освобождённое место, запуск GC, проверка целостности данных после GC. |
| `--import` | `<путь_к_файлу_в_Linux>` | Копирует файл из обычной файловой системы Linux на флеш под тем же именем. |
| `--export` | `<имя_файла_на_флеше>` | Копирует файл с флеша обратно в файловую систему Linux (перезаписывает файл с тем же именем в текущей директории). |
| `--info` | — | Диагностический дамп: размер структуры инода, состояние таблицы учёта секторов (generation, номера страниц), содержимое всех копий inode-таблицы и первых секторов области данных в hex. |

### Примеры

```bash
# Форматирование
sudo ./main --reset_flash

# Запись и чтение файла
sudo ./main --write photo.bin 20000
sudo ./main --read  photo.bin 20000

# Импорт реального файла с диска на флеш
sudo ./main --import ./notes.txt

# Экспорт обратно
sudo ./main --export notes.txt

# Удаление и сборка мусора
sudo ./main --del photo.bin
sudo ./main --inode

# Полный автоматический тест
sudo ./main --test
```

## 6. Внутреннее устройство (кратко)

- **Учёт секторов** (`flash_ops/flash_top_oper.h`): 4 зеркальные копии
  таблицы `{использовано_байт, счётчик_стираний}` на каждый сектор,
  выбор самой свежей копии по generation-номеру (round-robin запись
  защищает от потери данных при обрыве питания).
- **Экстенты** (`file_system/extent.h`): файл длиннее одного сектора
  или не помещающийся в единый непрерывный участок описывается
  массивом `{addr, len}` — `fragmentation_file()` собирает нужное
  число секторов из нескольких прогонов свободного места.
- **Inode-таблица** (`file_system/indode.h`, `FS_fops.h`): 128 файлов,
  до 8 экстентов на файл, 4 зеркальные копии по тому же принципу
  generation-версионирования, что и таблица секторов.
- **Garbage collection**: сектор считается кандидатом на очистку, если
  доля неактуальных (перезаписанных/удалённых) байт в нём ≥ 90%; живые
  файлы из таких секторов переносятся в новое место перед стиранием.

## Известные ограничения

- Внутренняя адресация рассчитана на 1024 сектора (4 МиБ). На чипе
  W25Q64FV (8 МиБ) верхняя половина физического объёма сейчас не
  используется.
- Нет журналирования на уровне inode-таблицы отдельно от generation-
  защиты — обрыв питания посреди `write_inode_table` защищён (старая
  копия остаётся валидной), но обрыв между записью данных и
  обновлением инода может оставить неиспользуемые данные на флеше
  (не критично, устраняется сборщиком мусора).
- Максимум 128 файлов и 8 экстентов на файл — при более сильной
  фрагментации запись может завершиться ошибкой (`write_file`
  возвращает `-1`).
